# Security and evidence handling

This repository contains sanitized research data and inert tooling. It contains no captured executables, live reporting keys, provider email ledger or original network payloads. Do not submit them in issues or pull requests. Quoted source material is untrusted data and must never be executed as part of loading or evaluation.

To report a privacy concern, use GitHub's private vulnerability reporting when available; otherwise open an issue that states only that a private contact channel is needed. Include a row identifier, not identifying evidence, in a public report. Maintainers should preserve the affected version privately, investigate, and publish a corrected version with a clear removal notice. Deleting a current file cannot recall previous public downloads.

Do not connect generated triage responses directly to autonomous provider reporting, law-enforcement complaints, account blocking or production changes. Independent validation, authorization, current contact verification and duplicate-report checks are required. No real-world malicious attribution follows solely from the labels.
